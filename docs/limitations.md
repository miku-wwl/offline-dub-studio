# Known limitations

- No complete end-to-end model-backed conversion is claimed until it is run and inspected on real media.
- `faster-whisper-small` and `tiny` run on CPU `int8`; recognition quality and speed vary substantially by source audio.
- Argos translates each recognized segment individually. It does not carry scene-long context or a glossary across a movie.
- Kokoro produces English voices. English-to-Chinese TTS is not implemented, so the public job API currently accepts only Chinese-to-English jobs.
- Automatic speaker diarization is not implemented. Transcript segments initially use `speaker_1`; users manually assign/merge stable IDs and select different Kokoro voices.
- Demucs is archived upstream and splits musical vocals from accompaniment. It is not a film-dialogue separator; effects may be lost and residual original voices may remain.
- Faster English TTS may exceed Mandarin cue duration. Phase 2.6 first trims only low-energy outer padding with 40 ms retained, then applies bounded `atempo` (default 1.25×, configurable up to 1.3×). Overflow is measured and retained; source interval overlaps are distinguished from generated collisions. Nontrivial speech extending beyond the video blocks application export for translation/timing correction. Energy-based padding detection is not phoneme-level proof; listen for clipped quiet consonants or breath.
- Project glossary terms are snapshotted into each new job. Argos can corrupt protection markers; the fallback inserts exact terms and translates every surrounding source span, which can produce awkward grammar. Adjacent source dialogue is exposed for manual review. Automatic scene-context translation and semantic equivalence of shortened wording are not verified. Reviewed text and original model text/provenance are retained; no external LLM is used.
- Balanced subtitle processing checks outlined glyph presence per frame and uses short geometry/content-checked OCR anchors. Scene changes reset tracking; missing glyphs do not inherit old masks. Low-confidence text, logos, unusual alignments or non-white styles can still be missed/confused. Search rectangles and explicit timed masks have different meanings: a search rectangle constrains recognition; a timed mask forces repair independently of OCR only within its interval. Inspect actual source frames and all scene transitions.
- OpenCV Telea/Navier-Stokes inpainting is a baseline. It cannot reconstruct obscured imagery and may smear edges. Historical OCR boxes are never accumulated into a global mask. A scene change cannot inherit a previous frame's boxes; erroneous text recognition within the new scene is still possible.
- Search rectangles are editable in the existing preview workflow. Masks are saved in `ocr-trace.json` as timestamped intervals. Review previews show the first masked frame, which cannot represent every scene. Inspect the final MP4 across the full sample.
- Masked Phase 2.6 jobs store a lossless FFV1 subtitle strip overlaid onto the original at final H.264 encode. This avoids two lossy encodes and reduces storage when text occupies a narrow band. No detections means no repair intermediate. A large union of regions can still require a full-height strip. Unmasked pixels must remain unchanged before final encoding and caption burn-in.
- The restoration bank contains sampled subtitle strips within ±2 seconds and only uses references from the same detected scene with motion/context checks. Conservative whole-line reference exclusions reduce reintroduced text. Unsupported pixels use aligned boundary interpolation and spatial inpainting. Occluded hands, microphones, seams and scenery cannot be recovered reliably; smears, stretched detail, ghosting and visible bands remain possible. Scene detection and optical flow are approximations, not semantic scene understanding.
- Final mixing/export is 48 kHz stereo. Kokoro's native 24 kHz speech is upsampled once after fitting; this does not restore missing high frequencies. Demucs htdemucs has a native 44.1 kHz processing path, so a 48 kHz export cannot recover frequencies lost during separation. Stereo preservation and sample-rate correctness do not establish perceptual ambience/effects preservation.
- Timeline mixing uses one-second audio buffers and a float scratch WAV. It records each segment's generated end, overflow, collision, and truncated tail; it does not fix every timing problem automatically. Review any tail-loss warning before accepting an export.
- Demucs still loads long audio into memory and its subprocess cannot be cancelled until it exits. FFmpeg extraction/render cancellation is also checked at stage boundaries. OCR and timeline composition have frequent cancellation checkpoints. Resume reuses completed stages with existing artifacts; it does not resume halfway through Demucs/OCR/render or prove cache integrity against malicious file tampering.
- Original import snapshots, source/stem WAVs, a float timeline scratch file, repaired frames, and encoded exports all consume disk. Stereo 44.1 kHz PCM alone uses about 1.27 GB per two hours; float 24 kHz stereo uses about 1.38 GB. FFV1 size depends heavily on footage and can dominate storage. Disk exhaustion remains a long-video risk.
- Two-hour processing is not accepted. Extrapolating a 60-second CPU sample does not establish sustained memory, disk, timing, or subjective quality. The 60-second human quality gate must pass first.
- This release does not provide a user-configurable quality/GPU mode, pyannote, voice cloning, PaddleOCR, Paddle inpainting, or a subtitle-removal neural model.
- No registry release or clean-machine offline acceptance has occurred yet.
